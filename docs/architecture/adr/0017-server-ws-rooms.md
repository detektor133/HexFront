# ADR-0017: Сервер матчей — ядро комнаты без сети, `ws`, один процесс

**Статус:** принято · 2026-11-11

## Контекст
Этап 09 переводит матч на авторитетный сервер (ADR-0002). Локальный режим уже работает по тому же протоколу снимков и дельт, поэтому сервер должен переиспользовать его, а не повторять. Целевая машина — дешёвый VPS (1 vCPU, 512 МБ): процессор ограничивает число комнат, память — нет (комната ≈ 3–4 МБ).

## Решение
1. **Ядро комнаты не знает про сеть** (`apps/server/src/room.ts`): соединение — интерфейс `Connection { send, close }`, время приходит снаружи. Вся логика (набор, старт, тик, туман, дельты, лимит команд, реконнект, передача боту) тестируется без сокетов и без реального времени.
2. **`Hub`** (`hub.ts`) сопоставляет подключения с комнатами (открытая комната, закрытая по коду, реконнект по токену) и ведёт тики 10 Гц всех комнат одним планировщиком: следующий запуск считается от плана, отставание догоняется не больше чем на 3 тика, дальше долг сбрасывается.
3. **Транспорт — `ws`** (`server.ts`): HTTP и WebSocket на одном порту, `/healthz`, `maxPayload` 8 КБ, соединение с очередью отправки больше 4 МБ обрывается. `ws` — библиотека из утверждённого стека (AGENTS.md §2), других зависимостей нет.
4. **Поток дельт один на клиент и сервер**: `ConfirmedViewDeltaStream` перенесён в `packages/protocol`. База дельты — только подтверждённый `viewAck` вид; потерянное подтверждение (100 тиков) сбрасывает поток на полный снимок.
5. **Недоверенный ввод**: сообщение клиента разбирается вручную (`decodeClientMessage`), команда проходит `validateCommand` (белый список типов, простые поля ограниченного размера, поле `source` запрещено). Смысл команды проверяет sim.
6. **События по игроку**: клиент получает свои события и политические (захват города, выбывание, победа, дипломатия с его участием); чужие внутренние события не уходят.
7. **(Заменено ADR-0018: шлюз и пул шардов-воркеров.)** Исходно: один процесс, комнаты по очереди. `worker_threads` на комнату (T2) откладывается до нагрузочных замеров: тик комнаты ≈ 5–6 мс, 6 комнат занимают ≈ 1/3 тика. Если замер на VPS покажет, что планировщик не справляется, комната переезжает в воркер без изменений ядра (оно не зависит от потока).
8. **Логирование** — JSON-строки в stdout без `pino`: одна функция на `Hub`. Библиотека логов подключается ADR, когда понадобятся уровни и ротация.

## Последствия
+ Сетевой слой тонкий (≈ 60 строк), основная логика проверяется быстрыми юнит-тестами.
+ Клиент и сервер используют один и тот же поток дельт, расхождения невозможны.
− Один зависший расчёт комнаты задерживает все комнаты процесса, пока не введены воркеры; защита — лимит комнат на процесс и нагрузочный тест.
− Трафик 3–5 КБ/с на игрока без сжатия (≈ 1,7 КБ/с после deflate); `permessage-deflate` на `ws` выключен до замера CPU, бинарный кодек не требуется.
