# ADR-0008: Инкрементальный рендер карты и дельта-снимки

**Статус:** принято · 2026-10-06

## Контекст

`economy-layer.setView` и `redraw()` перестраивают заливку, дороги, границы, туман и метки на каждый снимок. При изменении масштаба тот же объём работы выполняется на каждом шаге. Полный снимок также заставляет клиент и воркер обрабатывать данные, которые не изменились.

## Решение

1. Территория, границы и туман делятся на чанки 16×16 гексов; каждый чанк имеет собственный `Graphics` и перерисовывается только при изменении данных внутри него.
2. Дороги перестраиваются только при изменении дорожной сети.
3. Геометрия перестраивается только при смене уровня детализации; шаги масштаба внутри уровня меняют только трансформацию.
4. Воркер и сервер отправляют дельту относительно последнего подтверждённого снимка. Полный снимок отправляется при старте, смене вида и смене режима тумана.
5. Бюджет обработки ботов распределяется планировщиком по тикам. WebAssembly и нативный код не используются, пока профиль после выполнения решений 1–5 не покажет горячий цикл симуляции выше бюджета.

## Бюджеты

- Полный тик `step + боты + снимок`: в среднем не более 15 мс для 30 ботов и 40 мс для 100 ботов на всём матче до 25:00, Node 22, одно ядро.
- Клиентский кадр: p95 не более 33 мс в сценарии 5× за 10 минут.

## Последствия

+ Неизменившиеся слои не тратят время на построение геометрии.
+ Дельта содержит только изменения после подтверждённой базы и становится форматом для серверного протокола.
− Реализация хранит инвалидированные чанки и базовый подтверждённый снимок.
− Для полного снимка нужны отдельные пути синхронизации при старте и смене вида или тумана.
