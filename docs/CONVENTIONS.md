# Соглашения разработки

Обязательны для агента и человека. Нарушение — повод отклонить задачу.

## 1. Языки

| Что | Язык |
| --- | --- |
| Сообщения коммитов, описания PR, отчёты, документация | **Русский** |
| Комментарии в коде, JSDoc | **Русский** |
| Названия тестов (`describe`/`it`) | **Русский** — читаются владельцем в отчётах |
| Идентификаторы (переменные, функции, типы, файлы), ветки, теги | Английский (латиница) |
| Тип коммита (`feat`, `fix` …) | Латиница — для автоматической проверки и фильтрации истории |
| Тексты интерфейса | Только через словари `i18n` (ru/en), никогда строкой в коде |
| Логи сервера | Английский: короткий ключ события + структурированные поля (`{ event: 'room_tick_slow', ms: 14 }`) |

## 2. Git

### Ветки

| Ветка | Назначение |
| --- | --- |
| `main` | Всегда зелёная, только через PR (кроме `docs:` без кода) |
| `stage-02` | Работа над этапом |
| `fix/supply-split-crash` | Срочное исправление вне этапа |
| `cr/003-naval` | Применение Change Request |

Имена веток — латиница, `kebab-case`.

### Сообщение коммита

```
<тип>(<область>): <что сделано — по-русски, с маленькой буквы, без точки в конце>

<зачем и как, если не очевидно из заголовка — по-русски, строки до 100 символов>

Этап: 02/T5
Решение: DECISIONS 2026-09-23 | CR-003
```

- Заголовок ≤ 72 символов, повелительное или прошедшее время — одно на весь проект: **прошедшее** («добавлен», «исправлено»).
- Строки `Этап:` и `Решение:` — трейлеры. `Этап:` обязателен для коммитов в ветке этапа. `Решение:` обязателен для типов `balance` и `change` и при любом обновлении golden-хэшей или эталонов скриншотов.

**Типы:**

| Тип | Когда |
| --- | --- |
| `feat` | Новая возможность по задаче этапа |
| `fix` | Исправление ошибки (с тестом, воспроизводящим ошибку) |
| `test` | Только тесты |
| `refactor` | Изменение структуры без изменения поведения (хэши реплеев не меняются) |
| `perf` | Производительность без изменения поведения |
| `balance` | Изменение чисел в `10-balance.md` + `balance.ts` |
| `change` | Изменение правила по решению владельца (размер M) или CR |
| `docs` | Только документация |
| `build` / `ci` / `chore` | Сборка, CI, служебное |

**Области:** `sim`, `protocol`, `mapgen`, `client`, `server`, `bots`, `balance-tool`, `infra`, `docs`.

**Примеры:**

```
feat(sim): добавлена система сетей снабжения и изоляции городов

Сети пересчитываются раз в секунду, пересчёт размазан по игрокам
через tick % 10, чтобы не было пиков нагрузки.

Этап: 02/T7
```

```
fix(sim): армия больше не отступает в гекс с тремя своими армиями

Выбор гекса отступления не учитывал MAX_ARMIES_PER_HEX.
Добавлен сценарий «соседи переполнены → капитуляция».

Этап: 03/T6
```

```
balance(sim): максимальный налог поднят с 40 до 50 %

Решение: DECISIONS 2026-10-02
```

### Правила коммитов

- Один коммит — одно логическое изменение. Код и его тесты — в одном коммите.
- Каждый коммит собирается и проходит `pnpm check` (чтобы работал `git bisect`).
- Не коммитить: секреты, `.env`, сгенерированные сборки, большие исходные данные (Natural Earth и т. п.).
- `git push --force` в `main` запрещён. В своей ветке — только до открытия PR.
- Откат — `git revert`, не ручная правка.

### PR и теги

- Заголовок PR — в формате коммита. Описание — по шаблону `.github/pull_request_template.md`.
- Тег после приёмки этапа: `stage-02-done`. Релизы: `v0.<этап>.<патч>` (`v0.7.0` — soft launch).

## 3. Комментарии в коде

**Главное правило: комментарий объясняет «почему», а не «что».** Что делает код, должно быть видно из имён.

### Обязательно

- **Заголовок файла системы** `sim` — одна–две строки: что за механика и ссылка на раздел GDD:
  ```ts
  // Сети снабжения: компоненты связности дорог и городов, изоляция от столицы.
  // GDD: docs/gdd/04-roads-supply.md — «Сети снабжения»
  ```
- **JSDoc на всех экспортируемых функциях `sim`** — по-русски, с единицами измерения и форматом чисел:
  ```ts
  /**
   * Снабжённость армии с учётом сети и потерь вне дорог.
   * @returns доля 0..1 в fixed-point (1000 = 100 %)
   */
  export function armySupplyLevel(state: MatchState, army: Army): Fp { … }
  ```
- **Формула из GDD** — комментарий с формулой в той же записи, что в документе, рядом с реализацией.
- **Неочевидное решение** — почему так, а не проще: «сортировка по hexId нужна для детерминизма tie-break».
- **Обход бага библиотеки/браузера** — что за баг, ссылка на issue, когда можно убрать.

### Запрещено

- Комментарии-пересказы: `// увеличиваем счётчик` над `count++`.
- Закомментированный код — удалять, история есть в git.
- История изменений в коде (`// изменено 12.10: …`) — это работа git.
- «Разговорные» комментарии агента: `// Здесь мы теперь…`, `// Исправленная версия`, `// Как вы просили`.
- `TODO` без привязки. Формат только: `// TODO(stage-04/T3): подсветка пути перестройки` — и задача должна существовать.
- `eslint-disable` и `@ts-ignore`/`@ts-expect-error` без комментария с причиной; в `sim` — запрещены вовсе.

## 4. Стиль кода

### Форматирование

Prettier, конфиг в корне: `printWidth: 100`, `singleQuote: true`, `trailingComma: 'all'`, `semi: true`, `arrowParens: 'always'`. Не спорить со форматтером, не форматировать руками.

### Имена

| Что | Стиль | Пример |
| --- | --- | --- |
| Файлы | `kebab-case.ts` | `supply-network.ts` |
| Функции, переменные | `camelCase`, глагол для функций | `computeNetworks`, `isIsolated` |
| Типы, интерфейсы | `PascalCase`, без префикса `I` | `SupplyNetwork` |
| Константы баланса | `SCREAMING_SNAKE` | `CITY_MIN_DISTANCE` |
| Булевы | `is/has/can` | `hasRoad`, `canFoundCity` |
| Fixed-point значения | тип `Fp`, без суффиксов в имени | `supplyLevel: Fp` |
| Единицы времени | суффикс единицы | `buildTimeTicks`, `durationS`, `tickMs` |

### TypeScript

- Только именованные экспорты, `export default` запрещён.
- `index.ts` — только в корне пакета (публичный API). Внутри пакета — прямые импорты файлов.
- Порядок импортов: node → внешние → пакеты монорепо → относительные (автоматически через ESLint).
- Данные — `readonly` там, где не мутируются. Типы-объединения с дискриминатором `t`/`kind`, `switch` с `assertNever` в `default`.
- В `sim` — функции и данные, без классов (кроме неизбежного, через ADR).
- Нет `any`. `unknown` — только на границах (разбор сетевых сообщений, JSON) с последующей валидацией.
- Ошибки ожидаемые (невалидная команда) — возвращаемое значение `Result`/`Rejected`, не исключение. Исключения — только для нарушенных инвариантов (баг).

### React (`apps/client/src/ui`)

- Функциональные компоненты, один компонент на файл, `PascalCase.tsx`.
- Состояние — `useState`/`useReducer`; данные матча — через один стор на `useSyncExternalStore`.
- Стили — CSS Modules + CSS-переменные из сгенерированного `tokens.css`. Инлайн-стили — только для динамических значений (позиция, ширина полосы).
- Никаких литералов цветов, отступов, радиусов вне токенов.

### Тесты

- Файл рядом с кодом: `supply-network.test.ts`; сценарии — `packages/sim/test/scenarios/<механика>.test.ts`.
- Названия по-русски, в форме утверждения:
  ```ts
  describe('отступление', () => {
    it('армия отступает в соседний свой гекс, когда org падает до нуля', …);
    it('армия капитулирует, если все соседние гексы чужие', …);
  });
  ```
- Один `it` — одно поведение. Без `sleep` и реального времени — только тики.

## 5. Отчёты и документы

- Markdown, русский, короткие предложения, таблицы для сравнений.
- Даты — `YYYY-MM-DD`. Числа в тексте — по-русски (`1,5`, `20 %`); в коде и токенах — как в коде.
