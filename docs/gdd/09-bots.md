# GDD 09 — Боты

Боты обязательны: заполняют лобби, делают первые матчи новичков интересными, служат инструментом баланса (headless-матчи).

## Архитектура

- Бот — чистая функция от состояния матча и общего контекста тика → `Command[]`, вызывается раз в `BOT_THINK_TICKS` (со смещением по id, чтобы не все в один тик). Отдельной памяти у бота нет: его задачи — планы армий в состоянии матча (раздел «Utility AI»).
- Бот видит **только** то, что видел бы игрок (тот же туман): вражеские отряды — только в его зоне обзора. Никакого читерства.
- Бот выдаёт **те же команды**, что клиент игрока. Отдельных «бот-API» в `sim` нет.
- Случайность — seeded PRNG бота (сид = сид матча + id игрока).
- Уровень бота (`easy` или `medium`) передаётся необязательным массивом по id игрока рядом с массивом `bots` в `commanderCommands` и `botCommands`; отсутствующий уровень означает `medium`. Уровень не входит в `MatchState` и его хэш.
- **Военная часть бота — commander** (`07-controls.md`, «Автокомандование»): армии бота — с auto, отдельных приказов бот им не отдаёт. Utility AI ниже — экономика и крупные решения (налог, стройки, набор, дорога, когда нажать ▶ «Начать» на армии).

## Utility AI

- Решение бота раз в `BOT_THINK_TICKS` (easy — `BOT_EASY_THINK_TICKS`), только в его ход: снимок бота → оценки целей → выбор → команды.
- Снимок бота строится из общего контекста тика (свои и пограничные гексы, отряды, армии, города, планы по игроку) и индекса «гекс → отряды», без `playerView` и без прохода по всей карте. Контакт с врагом E: `mine(E)` — свои солдаты на своих гексах у границы с E; `theirs(E)` — солдаты E на его гексах у этой границы, только в зоне обзора бота (при `fog: false` — все). Доход — по базам дохода контекста, содержание — по своим отрядам.
- Задачи бота хранятся в состоянии матча, отдельной памяти бота нет: наступление на E — фронт армии на куске границы с E с `startWanted` или активным наступлением (текущая цель); оборона — остальные фронты; экспансия — армия без плана; стройки и набор — очереди.
- Полезность каждой цели = вес `BOT_W_*` × факторы 0..1 (fixed-point, `clamp01` — ограничение 0..1). Веса и пороги — `10-balance.md`, «Боты».

| Цель | Полезность | Действие |
| --- | --- | --- |
| Дорога | `BOT_W_ROAD`, если есть свой изолированный город с путём для дороги | `rebuildSupply` |
| Оборона | `BOT_W_DEFEND` × max по E `need(E)`, `need = clamp01((theirs × BOT_ARMY_RATIO − mine) / theirs)` | набор; при золоте > `BOT_GOLD_TARGET` ещё форт на своём гексе против самого крупного видимого стека E: `BOT_W_FORT × need × pressure` |
| Наступление на E | `BOT_W_ATTACK × clamp01((ratio − BOT_ATTACK_MIN_RATIO) / (BOT_RATIO_CAP − BOT_ATTACK_MIN_RATIO))` × (1 + `BOT_ELIM_BONUS`, если у E не больше `BOT_ELIM_CITIES` городов) × (1 + `BOT_TARGET_STICKY`, если E — текущая цель); `ratio = min(mine / theirs, BOT_RATIO_CAP)` | цель одна — лучшая E (при равенстве меньше городов, затем меньший id): ▶ армии на куске с E, не больше `MAX_ACTIVE_ARROWS` наступлений; ■ на активном наступлении, если `ratio < BOT_ATTACK_STOP_RATIO` |
| Набор | `BOT_W_RECRUIT × max(need_max, attackNeed, pressure)`; `attackNeed = clamp01((theirs × BOT_ATTACK_MIN_RATIO − mine) / theirs)` для цели; `pressure = clamp01((золото − BOT_GOLD_TARGET) / BOT_GOLD_TARGET)` | `recruit` пехоты в каждом свободном своём городе по убыванию `recruitMax`; солдат = min(`recruitMax`, по золоту, по содержанию) шагом `RECRUIT_STEP`; бюджет содержания = доход × `BOT_ARMY_INCOME_SHARE` + золото / `BOT_GOLD_RUNWAY_S` |
| Основать город | `BOT_W_FOUND × pop/popCap` лучшего места × (1 + `pressure`) | `foundCity` |
| Улучшить город | `BOT_W_UPGRADE × (5 − уровень)/4` × (1 + `pressure`) | `upgradeCity` |
| Благоустройство | `BOT_W_IMPROVE × pop/popCap` × (1 + `pressure`) | `improve` |

- Места для города и благоустройства — только по своим гексам и кольцам своих городов; условия мест как сейчас (`CITY_MIN_DISTANCE`, `CITY_FOUND_MIN_POP_RATIO`, `BOT_IMPROVE_POP_RATIO`).
- Налог: мир — `BOT_TAX_PEACE`, есть контакт с врагом — `BOT_TAX_WAR`, золото < `BOT_GOLD_RESERVE` при минусовом балансе — `TAX_MAX`.
- Армия экспансии: пока своя земля граничит с ничьей, а все армии заняты планами — `createArmy`. Автопополнение бот включает. Захват нейтральных городов и ничьей земли — commander (`07-controls.md`, «Автокомандование»).
- Выбор: кандидаты по убыванию полезности (при равенстве — порядок строк таблицы, затем меньший id); берутся с полезностью ≥ `BOT_MIN_UTILITY`; трат за решение не больше `BOT_MAX_SPENDS`, резерв `BOT_GOLD_RESERVE` сохраняется. Прогноз боя мозг не вызывает: ▶ решает `ratio`.
- **Путь ботов в commander** (только армии ботов; армии людей и игроков без бота — без изменений, правило `07-controls.md` «лишние отряды — в самую слабую армию» для них остаётся): резерв и новые отряды — в армию цели (`startWanted` или активное наступление), если её нет — по старому правилу; свой отряд меньше `BOT_MERGE_BELOW` солдат, не в бою и не отступающий, идёт в гекс ближайшего однотипного отряда своей армии в радиусе `BOT_MERGE_RADIUS` (в гексе меньше 3 отрядов) и там сливается. Команды идут с `source: 'auto'` и auto не выключают.
- Уровни: easy — цель «Наступление» выключена, налог `BOT_EASY_TAX`; commander у easy и medium одинаковый.

## Уровни

Уровни — параметры utility AI и commander.

| Уровень | Отличия |
| --- | --- |
| Лёгкий | Экономический мозг реагирует раз в 3 с, не нажимает ▶ «Начать», не использует линии наступления для окружений, налог фиксированный 20 %; commander работает без изменений |
| Средний (по умолчанию) | Реакция 1 с, наступает на слабые участки |
| Сложный `[ПОЗЖЕ]` | Целенаправленно режет дороги, ищет котлы |

Новичку в первых 3 матчах — больше лёгких ботов по соседству.
