# GDD 09 — Боты

Боты обязательны: заполняют лобби, делают первые матчи новичков интересными, служат инструментом баланса (headless-матчи).

## Архитектура

- Бот — чистая функция от состояния матча и общего контекста тика → `Command[]`, вызывается раз в `BOT_THINK_TICKS` (со смещением по id, чтобы не все в один тик). Отдельной памяти у бота нет: его задачи — планы армий в состоянии матча (раздел «Utility AI»).
- Бот видит **только** то, что видел бы игрок (тот же туман): вражеские отряды — только в его зоне обзора. Никакого читерства.
- Бот выдаёт **те же команды**, что клиент игрока. Отдельных «бот-API» в `sim` нет.
- Случайность — seeded PRNG бота (сид = сид матча + id игрока).
- Уровень бота (`easy` или `medium`) передаётся необязательным массивом по id игрока рядом с массивом `bots` в `commanderCommands` и `botCommands`; отсутствующий уровень означает `medium`. Уровень не входит в `MatchState` и его хэш.
- **Военная часть бота — commander** (`07-controls.md`, «Автокомандование»): армии бота — с auto, отдельных приказов бот им не отдаёт. Utility AI ниже — экономика и крупные решения (налог, стройки, набор, дорога, когда нажать ▶ «Начать» на армии).

## Utility AI

- Решение бота — раз в `BOT_THINK_TICKS` (easy — `BOT_EASY_THINK_TICKS`), только в его ход: снимок (`bots/snapshot.ts`) → каталог действий → признаки → оценка по весам → команды.
- Каталог действий — функция от определений игры, по умолчанию из `balance.ts`, а не список в коде бота. Набор создаётся для каждого типа юнита из таблиц `COST_GOLD_PER_SOLDIER`, `UPKEEP_GOLD_PER_SOLDIER_S`, `ATK`, `DEF`, `SUPPLY_PER_SOLDIER` в каждом свободном своём городе. Стройка создаётся для каждого вида из `BUILDING_DEFS` на граничных гексах и гексах своих городов; `BUILDING_DEFS` собирается из существующих констант `FORT_*` и `DEPOT_*`. `upgradeCity`, `improve`, `foundCity`, `rebuildSupply` создаются для мест на своих гексах и кольцах своих городов с текущими условиями (`CITY_MIN_DISTANCE`, `CITY_FOUND_MIN_POP_RATIO`). ▶ и ■ создаются только для своих армий с фронтом на границе с врагом. Налог создаётся для ставок от `TAX_MIN` до `TAX_MAX` с шагом `TAX_STEP`. Новый тип юнита или постройки попадает в каталог без правки кода бота.
- Признаки — fixed-point, без float. Эффекты берутся из полей определения: цена в золоте, Δсодержания/с, Δдохода/с, Δсилы = солдаты × (`ATK + DEF`) типа, Δобороны = множитель обороны постройки или города × свои солдаты на гексе, Δснабжения. Каждый эффект считается относительно текущего значения бота: золота, дохода или силы. Контексты из снимка: угроза = max по врагам `theirs / (mine + theirs)`, запас золота = `золото / (золото + доход × 60 с)`, доля своих пограничных гексов у ничьей земли. Для каждого действия создаются признак эффекта и признак `эффект × каждый контекст`.
- Для ▶ и ■ используются признаки `mine / (mine + theirs)` у фронта, `1 / (1 + города врага)` и признак текущей цели.
- Оценка действия = Σ `вес × признак`, целые числа. Веса — данные `packages/sim/src/bots/weights.json`, подбираемые офлайн-обучением `tools/evolve`; вручную веса не правятся. Налог и ▶/■ выбираются по этим весам; easy использует фиксированный `BOT_EASY_TAX` и не создаёт ▶/■. Обучение в матче не ведётся: детерминизм обеспечивается ADR 0003, а бюджет тика — 15 мс.
- Берутся действия с оценкой > 0 по убыванию; при равенстве — порядок каталога, затем меньший id. Размер набора выбирается по доступному золоту сверх `BOT_GOLD_RESERVE` и вместимости города, округляется вниз до `RECRUIT_STEP`, но не ниже `RECRUIT_MIN`. Траты идут без лимита числа действий, пока золото ≥ цена + `BOT_GOLD_RESERVE`; на город или гекс выполняется одно действие за решение. ■ отправляется по оценке фронта: при неположительной оценке активного наступления.
- Армия экспансии создаётся по прежнему правилу. Автопополнение бот включает. Путь ботов в commander (резерв в армию цели, слияние малых отрядов, `BOT_MERGE_BELOW`, `BOT_MERGE_RADIUS`) остаётся без изменений.
- **Путь ботов в commander** (только армии ботов; армии людей и игроков без бота — без изменений, правило `07-controls.md` «лишние отряды — в самую слабую армию» для них остаётся): резерв и новые отряды — в армию цели (`startWanted` или активное наступление), если её нет — по старому правилу; свой отряд меньше `BOT_MERGE_BELOW` солдат, не в бою и не отступающий, идёт в гекс ближайшего однотипного отряда своей армии в радиусе `BOT_MERGE_RADIUS` (в гексе меньше 3 отрядов) и там сливается. Команды идут с `source: 'auto'` и auto не выключают.
- Уровни: easy — цель «Наступление» выключена, налог `BOT_EASY_TAX`; commander у easy и medium одинаковый.

## Уровни

Уровни — параметры utility AI и commander.

| Уровень | Отличия |
| --- | --- |
| Лёгкий | Использует те же веса, что и средний, не нажимает ▶ «Начать», налог `BOT_EASY_TAX`, решение раз в `BOT_EASY_THINK_TICKS`; commander работает без изменений |
| Средний (по умолчанию) | Реакция 1 с, наступает на слабые участки |
| Сложный `[ПОЗЖЕ]` | Целенаправленно режет дороги, ищет котлы |

Новичку в первых 3 матчах — больше лёгких ботов по соседству.

## Имена ботов

Список вымышленных «государств» (`Вельская республика`, `Северный союз` …) в `packages/mapgen/names/`. Боты помечены значком только в списке игроков, не на карте.
