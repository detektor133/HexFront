# GDD 01 — Карта

## Сетка

- Гексы **flat-top**, осевые координаты `(q, r)`, кубические для расстояний. Справочник: redblobgames.com/grids/hexagons.
- Соседи: 6 направлений, фиксированный порядок `SE, NE, N, NW, SW, S` (индексы 0–5) — порядок важен для детерминизма. Векторы в осевых координатах: `(+1,0) (+1,−1) (0,−1) (−1,0) (−1,+1) (0,+1)`; ось `r` направлена вниз по экрану.
- Карта хранится как плотный массив `width × height` со смещением (offset, even-q) для памяти; API — осевые координаты.
- Размер: ≈ **120 проходимых гексов на игрока** `[ТЮНИНГ]`. Генератор принимает от 2 до `MAPGEN_MAX_PLAYERS` игроков; для 30 игроков это около 3600 проходимых гексов и карта примерно 80×60, для 100 — около 12 000 проходимых гексов.

## Местность

| Местность | `terrain` | Проходима | Лимит населения | Время хода, с* | Оборона ×** |
| --- | --- | --- | --- | --- | --- |
| Равнина | `plains` | да | 100 | 2,0 | 1,0 |
| Лес | `forest` | да | 60 | 3,0 | 1,25 |
| Холмы | `hills` | да | 50 | 3,0 | 1,25 |
| Горы | `mountains` | да | 25 | 5,0 | 1,6 |
| Пустыня/степь | `desert` | да | 30 | 2,5 | 1,0 |
| Вода | `water` | нет | — | — | — |

\* базовое время на переход в гекс для скорости 1,0. \** множитель обороны защитника. Все числа — в `10-balance.md`.

- **Реки** — свойство **ребра** между двумя гексами (`riverEdges`), а не гекса. Переход через реку: +1,0 с к ходу, атакующий через реку ×0,7.
- **Особые гексы** (`feature`) для реиграбельности:
  - `fertile` — лимит населения ×1,5;
  - `mine` — +1 золото/с владельцу;
  - `pass` — горный перевал: время хода как у холмов.

## Объекты на карте при старте

- **Нейтральные города**: ~1,5 на игрока, уровни 1–3, с гарнизоном (см. `10-balance.md`). Минимальная дистанция между любыми городами — **4 гекса**.
- **Дороги**: генерируются между нейтральными городами (и стартовыми столицами) — минимальное остовное дерево + ~20 % дополнительных рёбер из триангуляции Делоне, путь по A* с весами местности, вода и горы (кроме перевалов) непроходимы для дорог.
- **Стартовые позиции**: столица игрока уровня 1, равноудалённые (Poisson-disc, минимум 10 гексов между столицами), на равнине/лесу, в радиусе 2 — ≥ 15 проходимых гексов.

## Типы карт

1. **Процедурные** `[MVP]` — генератор `packages/mapgen`, сид → карта. Правила ниже используют параметры из раздела «Генератор карт» в `10-balance.md`.

### Процедурные

#### Рельеф и биомы

- Высота — собственный целочисленный value-noise в диапазоне 0..1000, 3 октавы; сид и отдельные потоки влажности берутся из `rng.ts`.
- Из высоты вычитается спад к краю карты. Полоса шириной MAPGEN_EDGE_WATER гексов у края всегда является водой.
- Водой становятся нижние MAPGEN_WATER_SHARE гексов по высоте: используется квантиль по карте, а не фиксированный порог шума. Острова меньше MAPGEN_MIN_ISLAND гексов превращаются в воду.
- Среди суши верхние MAPGEN_MOUNTAIN_SHARE гексов становятся горами, следующие MAPGEN_HILLS_SHARE — холмами. Оставшаяся суша классифицируется отдельным шумом влажности: самые сухие MAPGEN_DESERT_SHARE — пустыня, самые влажные MAPGEN_FOREST_SHARE — лес, остальные — равнина.
- Все доли считаются от выборки, указанной в правиле. При равных значениях сортировка идёт по индексу гекса.

#### Особые гексы

- `fertile` размещается только на равнинах, цель — MAPGEN_FERTILE_PER_PLAYER на игрока.
- `mine` размещается только на холмах, цель — MAPGEN_MINE_PER_PLAYER на игрока.
- `pass` размещается на горе, у которой два противоположных соседа являются проходимой негорной сушей; максимум — один перевал на MAPGEN_PASS_PER_MOUNTAINS гексов гор.
- Кандидаты для всех особых гексов перемешиваются через `rng.ts` и выбираются по порядку. Особые гексы не ближе 3 гексов друг к другу, не находятся в радиусе 2 от стартовой позиции и не занимают город. Если кандидатов не хватает, размещается доступное количество без ошибки.

#### Реки

- Река строится по вершинам гексов; каждый её шаг помечает ребро между двумя гексами, которые разделяет отрезок.
- Высота вершины равна сумме высот трёх прилегающих гексов. Источник — вершина, касающаяся хотя бы одного холма или горы; источники не ближе 6 гексов друг к другу.
- На каждом шаге река переходит в соседнюю вершину с наименьшей высотой. При равенстве используется фиксированный порядок направлений. Река заканчивается на вершине, касающейся воды.
- Река отбрасывается, если достигает локального минимума, пересекает другую реку, имеет меньше MAPGEN_RIVER_MIN_EDGES или больше MAPGEN_RIVER_MAX_EDGES рёбер.
- Цель — MAPGEN_RIVERS_PER_PLAYER рек на игрока; кандидатов проверяется не более чем в 4 раза больше цели. Если цель не достигнута, генератор сохраняет столько рек, сколько прошло условия.

Размер карты подбирается при соотношении ширины и высоты 4:3 так, чтобы после построения рельефа и воды проходимых гексов было не меньше `PASSABLE_HEXES_PER_PLAYER` на игрока. При нехватке ширина и высота увеличиваются на 2, после чего шаги рельефа и воды повторяются. Города, ресурсы, реки, дороги и спавны масштабируются теми же параметрами на игрока.
2. **Реальный рельеф** `[MVP: 1 карта «Европа»]` — импорт из подготовленного JSON (рельеф, вода, реки), **без политических границ и реальных названий стран**. Города — вымышленные названия (списки в `packages/mapgen/names/`).
3. **Ручные сценарии** `[ПОЗЖЕ]`.

## Формат карты (JSON, версия 1)

```json
{
  "version": 1,
  "id": "proc-8f3a",
  "width": 80, "height": 60,
  "terrain": "base64 Uint8Array (width*height)",
  "features": [{"q": 10, "r": 4, "type": "mine"}],
  "riverEdges": [[10, 4, 0]],
  "roads": "base64 bitset (width*height)",
  "cities": [{"id": 1, "q": 12, "r": 7, "name": "Вельск", "level": 2, "garrison": 300}],
  "spawns": [{"q": 30, "r": 20}]
}
```

`riverEdges`: `[q, r, dir]` — ребро от гекса в направлении `dir` (хранится только для dir 0–2, чтобы не дублировать).

Кодирование полей:

| Поле | Кодирование |
| --- | --- |
| `terrain` | байт на гекс по индексу `col + row × width` (offset even-q): 0 — `water`, 1 — `plains`, 2 — `forest`, 3 — `hills`, 4 — `mountains`, 5 — `desert` |
| `features[].type` | в памяти — байт на гекс: 0 — нет, 1 — `fertile`, 2 — `mine`, 3 — `pass` |
| `roads` | битсет: бит гекса `i` — в байте `i >> 3`, младший бит первый (`(byte >> (i & 7)) & 1`) |
| `spawns` | порядок в файле не важен: при старте матча спавны перемешиваются по сиду (`08-match.md`) |
