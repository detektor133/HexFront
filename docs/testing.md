# Стратегия тестирования

Цель: AI-агент не может «сломать тихо». Каждая механика закрыта тестами до того, как на неё опирается следующая.

## Пирамида

| Уровень | Инструмент | Что | Где |
| --- | --- | --- | --- |
| Юнит | Vitest | Формулы систем, hex-математика, fixed-point, валидация команд | `packages/*/src/**/*.test.ts` |
| Свойства (инварианты) | fast-check | Случайные карты и команды → инварианты не нарушаются | `packages/sim/test/invariants/` |
| Сценарии | Vitest + DSL | Мини-карты из ASCII, заданные команды, проверка исхода | `packages/sim/test/scenarios/` |
| Golden-реплеи | Vitest | Лог команд → хэш состояния совпадает с эталоном | `packages/sim/test/golden/` |
| Бенчмарк | Node + `perf_hooks` (`pnpm --filter @hexfront/bench step`) | `step` на синтетическом матче 30 игроков, 4000 гексов, 200 отрядов, 20 боёв | матч — `packages/sim/bench/`, замер — `tools/bench/` (в `sim` таймеры запрещены) |
| Интеграция | Vitest + реальный ws | Сервер: подключение, команды, туман, реконнект | `apps/server/test/` |
| E2E | Playwright | Главное меню → локальный матч → первые действия; реальная CSS-геометрия, переполнение и пересечения | `apps/client/tests/e2e/` |
| Баланс | `tools/balance` | 100 матчей ботов, метрики темпа (`gdd/00-overview.md`) | отчёт, не в CI |

Поведение React-компонентов (клики, открытие меню, состояние, эффекты, таймеры, `ResizeObserver`) проверяется в тестах клиента с суффиксом `.dom.test.tsx` через Testing Library и среду jsdom. SSR-рендер (`renderToStaticMarkup`) не выполняет эффекты, `ResizeObserver`, клики и состояние, поэтому для таких критериев он не подходит. Размеры, которые jsdom не считает, задаются в тесте подменой `ResizeObserver` и `getBoundingClientRect`; `Worker` и холст Pixi в таких тестах подменяются. jsdom не считает раскладку: `getBoundingClientRect` даёт нули, CSS-модули не применяются, поэтому положение и размер элемента проверяются по его собственному `style` (`element.style.left` и т. п.), а не по измерению.

Реальные `getBoundingClientRect`, `scrollWidth`, переполнение, переносы и пересечения CSS-элементов проверяются только Playwright E2E в Chromium. Для такого критерия `plan` и `spec` выбирают Playwright автоматически: это технический тестовый слой, а не вопрос владельцу. Моки геометрии в jsdom не заменяют браузерную проверку. Если нужного E2E-контура нет, исполнитель сначала добавляет его в рамках задачи; исход `PLAN: инфраструктура — <причина>` маршрутизируется исполнителю без остановки владельца.

Геометрические ассерты (ректы, пересечения, `scrollWidth`) можно формально удовлетворить вырожденным способом — например, сжать текст `transform: scaleX(...)` так, что он укладывается в границы, но выглядит искажённым. 2026-10-22: испробован визуальный гейт — автоматический снимок HUD перед push, который должен был смотреть `$review`; роль review в разрешённой среде не может открывать изображения (см. `docs/QUESTIONS.md`, закрыто), поэтому гейт убран. Вместо него — прямая проверка: `getComputedStyle(...).transform` у текстовых узлов HUD должен быть `none` (`hud-layout.spec.ts`, тег `@layout`); она не требует смотреть на картинку и ловит ровно этот класс дефекта числом, а не глазами.

## Уровни тестов

| Уровень | Команда | Где идёт | Что входит |
| --- | --- | --- | --- |
| Быстрый | `pnpm test`, `pnpm verify [--changed]` | workflow `ci` (`pnpm check`), ПК агента | все тесты, кроме `SLOW_TESTS` |
| Браузерный | `pnpm test:e2e:layout [файл]` | workflow `ci` после `pnpm check`, ПК агента для целевого E2E | Playwright E2E с тегом `@layout` в Chromium, включая CSS-геометрию |
| Перед push | `pnpm verify:prepush` | агентный цикл после финального review | точный `pnpm check` из CI и весь обязательный браузерный уровень; красный результат запрещает push |
| Полный | `pnpm test:all` | workflow `slow` на каждый push | все тесты, включая `SLOW_TESTS`, и покрытие `packages/sim` |

- `SLOW_TESTS` в `vitest.projects.ts` — файлы дольше 4 с на CI (property-тесты на сотни прогонов, golden, сверки с полным пересчётом, обучение). Список меняется только вместе с этой таблицей; тест `tools/ai-check/src/slow-tests.test.ts` падает, если файл из списка пропал.
- Таймаут теста в полном уровне — 120 с, только защита от зависания: скорость меряет `tools/bench`, а не таймаут теста.
- Тяжёлый тест не ослабляется ради скорости: он переносится в `SLOW_TESTS` и идёт в полном уровне с тем же числом прогонов.
- Агентный цикл после финального review запускает `pnpm verify:prepush`. Красный gate создаёт один пункт `КОД:` с локальной ошибкой и возвращает задачу исполнителю без push; зелёный gate разрешает push и ожидание `ci` точного SHA. Красный `slow` ставит исправление первым в очередь, `$stage-close` требует зелёный `slow` на HEAD.

## Сценарный DSL (обязателен с этапа 02)

Тесты механик пишутся на мини-картах в ASCII — их читает человек и пишет агент:

```ts
const s = scenario(`
  .  .  .  .  .
  .  A1 a  .  .
  .  a  a  b  .
  .  .  b  B1 .
`, { legend: { A1: city('A', 1, { capital: true }), a: own('A'), b: own('B'), B1: city('B', 1, { capital: true }) } });

s.unit('A', 'infantry', 500, at(1, 2));
s.unit('B', 'infantry', 200, at(2, 3));
s.cmd('A', attack([unitOf('A')], at(2, 3)));
s.runSeconds(60);

expect(s.owner(at(2, 3))).toBe('A');
expect(s.unitsOf('B')).toHaveLength(1);            // отступил, а не исчез
expect(s.lastEvent('unitRetreated')).toBeDefined();
```

## Обязательные инварианты (fast-check, после каждого тика)

1. `soldiers ≥ 0`, `pop ≥ 0`, `gold ≥ 0`, `0 ≤ org ≤ ORG_MAX`, `0 ≤ supplyLevel ≤ 1`.
2. Все числа — целые, в пределах `Number.MAX_SAFE_INTEGER`.
3. В гексе нет отрядов двух разных владельцев. В гексе ≤ `MAX_UNITS_PER_HEX` отрядов. Отряд состоит не более чем в одной армии; армия и её отряды — одного владельца.
4. Армия стоит на проходимом гексе; артиллерия — только на своём.
5. Каждый город принадлежит владельцу своего гекса.
6. У живого игрока ровно одна столица, если есть города.
7. Сумма населения не растёт быстрее, чем максимум по формуле роста (нет «создания из ничего»).
8. `hashState(step(clone(s), cmds)) === hashState(step(clone(s), cmds))` — повторяемость.
9. Отклонённая команда не меняет хэш.

## Обязательные краевые случаи (по механикам)

- **Снабжение**: разрез единственной дороги → изоляция через ≤ 1 с; обход по своей территории → `rebuildSupply` доступен и восстанавливает связь; полное окружение → `supplyLevel = 0`, истощение после 20 с.
- **Отступление**: есть куда отступить → отряд жив и в соседнем своём гексе; все соседи чужие → капитуляция; соседи переполнены (3 отряда) → капитуляция; цепочка отступлений.
- **Артиллерия**: не входит в чужой гекс; одна при атаке → бегство с −10 %; бонус +30 % не складывается от двух батарей.
- **Экономика**: налог 0/20/40 → множители роста 1,4/1,0/0,5; инерция налога; банкротство блокирует набор, не уводит золото в минус.
- **Города**: дистанция 3 — отказ, 4 — ок; население 59 % — отказ; захват — выработка 25 % → 100 % за 60 с; потеря столицы → перенос.
- **Команды**: команда чужим отрядом или армией, несуществующий id, слишком частые команды — отклонены с причиной.

## Правила для агента

- Тест на баг пишется **до** исправления и падает без него.
- Приёмочные тесты задачи пишет до кода отдельная сессия `$spec` по тексту задачи. Исполнитель их не меняет. Reviewer возвращает `ТЕСТ:` автору тестов и `КОД:` исполнителю; оркестратор выдаёт по одному пункту и после каждого запускает узкую проверку.
- Нельзя ослаблять ассерты, удалять тесты, повышать пороги, чтобы стало зелёным — только через `docs/QUESTIONS.md`.
- Изменения состояния только для тестов (разрез дороги, смена владельца, задание населения) — через помощники сценарного DSL, **никогда** через команды `sim`: отладочные команды попали бы в протокол и на сервер.
- Покрытие `packages/sim` ≥ 90 % строк (проверка в workflow `slow`), но покрытие не заменяет инварианты и сценарии.
