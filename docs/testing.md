# Стратегия тестирования

Цель: AI-агент не может «сломать тихо». Каждая механика закрыта тестами до того, как на неё опирается следующая.

## Пирамида

| Уровень | Инструмент | Что | Где |
| --- | --- | --- | --- |
| Юнит | Vitest | Формулы систем, hex-математика, fixed-point, валидация команд | `packages/*/src/**/*.test.ts` |
| Свойства (инварианты) | fast-check | Случайные карты и команды → инварианты не нарушаются | `packages/sim/test/invariants/` |
| Сценарии | Vitest + DSL | Мини-карты из ASCII, заданные команды, проверка исхода | `packages/sim/test/scenarios/` |
| Golden-реплеи | Vitest | Лог команд → хэш состояния совпадает с эталоном | `packages/sim/test/golden/` |
| Бенчмарк | Vitest bench | `step` на эталонном матче 30 игроков | `packages/sim/bench/` |
| Интеграция | Vitest + реальный ws | Сервер: подключение, команды, туман, реконнект | `apps/server/test/` |
| Визуальные | Playwright | Скриншоты страниц `/dev/*` и экрана матча на 3 разрешениях | `apps/client/tests/visual/` |
| E2E | Playwright | Главное меню → локальный матч → первые действия | `apps/client/tests/e2e/` |
| Баланс | `tools/balance` | 100 матчей ботов, метрики темпа (`gdd/00-overview.md`) | отчёт, не в CI |

## Сценарный DSL (обязателен с этапа 02)

Тесты механик пишутся на мини-картах в ASCII — их читает человек и пишет агент:

```ts
const s = scenario(`
  .  .  .  .  .
  .  A1 a  .  .
  .  a  a  b  .
  .  .  b  B1 .
`, { legend: { A1: city('A', 1, { capital: true }), a: own('A'), b: own('B'), B1: city('B', 1, { capital: true }) } });

s.unit('A', 'infantry', 500, at(1, 2));
s.unit('B', 'infantry', 200, at(2, 3));
s.cmd('A', attack([unitOf('A')], at(2, 3)));
s.runSeconds(60);

expect(s.owner(at(2, 3))).toBe('A');
expect(s.unitsOf('B')).toHaveLength(1);            // отступил, а не исчез
expect(s.lastEvent('unitRetreated')).toBeDefined();
```

## Обязательные инварианты (fast-check, после каждого тика)

1. `soldiers ≥ 0`, `pop ≥ 0`, `gold ≥ 0`, `0 ≤ org ≤ ORG_MAX`, `0 ≤ supplyLevel ≤ 1`.
2. Все числа — целые, в пределах `Number.MAX_SAFE_INTEGER`.
3. В гексе нет отрядов двух разных владельцев. В гексе ≤ `MAX_UNITS_PER_HEX` отрядов. Отряд состоит не более чем в одной армии; армия и её отряды — одного владельца.
4. Армия стоит на проходимом гексе; артиллерия — только на своём.
5. Каждый город принадлежит владельцу своего гекса.
6. У живого игрока ровно одна столица, если есть города.
7. Сумма населения не растёт быстрее, чем максимум по формуле роста (нет «создания из ничего»).
8. `hashState(step(clone(s), cmds)) === hashState(step(clone(s), cmds))` — повторяемость.
9. Отклонённая команда не меняет хэш.

## Обязательные краевые случаи (по механикам)

- **Снабжение**: разрез единственной дороги → изоляция через ≤ 1 с; обход по своей территории → `rebuildSupply` доступен и восстанавливает связь; полное окружение → `supplyLevel = 0`, истощение после 20 с.
- **Отступление**: есть куда отступить → отряд жив и в соседнем своём гексе; все соседи чужие → капитуляция; соседи переполнены (3 отряда) → капитуляция; цепочка отступлений.
- **Артиллерия**: не входит в чужой гекс; одна при атаке → бегство с −10 %; бонус +30 % не складывается от двух батарей.
- **Экономика**: налог 0/20/40 → множители роста 1,4/1,0/0,5; инерция налога; банкротство блокирует набор, не уводит золото в минус.
- **Города**: дистанция 3 — отказ, 4 — ок; население 59 % — отказ; захват — выработка 25 % → 100 % за 60 с; потеря столицы → перенос.
- **Команды**: команда чужим отрядом или армией, несуществующий id, слишком частые команды — отклонены с причиной.

## Визуальные тесты (этап 04+)

- Dev-страницы: `/dev/units` (все состояния фишек), `/dev/map` (фиксированная карта-сцена со всеми слоями), `/dev/ui` (HUD, карточки во всех состояниях).
- Разрешения: 390×844, 844×390, 1440×900, DPR 1 и 3.
- Порог пиксельного расхождения 0,1 %. Обновление эталонов — только осознанно, с приложением новых PNG в отчёт этапа.
- Анимации в тестах заморожены (`?freezeTime=1`).

## Правила для агента

- Тест на баг пишется **до** исправления и падает без него.
- Нельзя ослаблять ассерты, удалять тесты, повышать пороги, чтобы стало зелёным — только через `docs/QUESTIONS.md`.
- Изменения состояния только для тестов (разрез дороги, смена владельца, задание населения) — через помощники сценарного DSL, **никогда** через команды `sim`: отладочные команды попали бы в протокол и на сервер.
- Покрытие `packages/sim` ≥ 90 % строк (проверка в CI), но покрытие не заменяет инварианты и сценарии.
