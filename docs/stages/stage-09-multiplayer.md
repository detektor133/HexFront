# Этап 09 — Мультиплеер

**Цель:** онлайн-матчи людей и ботов на авторитетном сервере с туманом, реконнектом и деплоем на staging.

**Читать:** `architecture/protocol.md`, `architecture/infra.md`, `architecture/adr/0002*`, `gdd/08-match.md`.

## Задачи

- [ ] **T1. `packages/protocol`**: типы C2S/S2C, JSON-кодек, версия, валидация входящих сообщений (ручная, без схем-библиотек; ADR, если нужна библиотека). Кодеки полного снимка и дельты уже есть (`packages/protocol`, 05/T12a): задача — добавить остальные сообщения из `architecture/protocol.md`.
- [ ] **T2. Сервер**: HTTP + ws на одном порту, `/healthz`, лобби «быстрый матч» (сбор 30 с или до максимума, затем боты), комната в `worker_threads`, тик 10 Гц с компенсацией дрейфа, логирование (ADR на pino).
- [ ] **T3. Туман на сервере**: `ViewDelta` по игроку, память вне обзора, политическая карта всем. `playerView` с туманом и памятью (04/T3), дельты и `viewAck` (05/T12) уже есть: задача — подключить их в комнате сервера.
- [ ] **T4. Клиентская сеть**: соединение, буфер 100 мс, интерполяция, отображение ack/rejected, индикатор пинга, переподключение.
- [ ] **T5. Реконнект и передача боту** через 30 с: армиям отключившегося включается auto, ими командует commander (CR-006). Сервер вызывает commander для армий с auto.
- [ ] **T6. Защита**: rate limit команд, лимит размера сообщений, валидация ников (длина, фильтр мата — простой словарь ru/en), не доверять клиенту ни в чём.
- [ ] **T7. Интеграционные тесты**: 2 клиента, команды, туман (клиент B не получает армию A вне обзора — проверка по сырым сообщениям), реконнект.
- [ ] **T8. Нагрузочный тест**: 10 комнат × 30 бот-клиентов по ws на одной машине 4 vCPU; метрики тика p99 и трафика в отчёт. Трафик > 4 КБ/с на игрока → ADR бинарного кодека. Бюджет построения снимка на игрока — по `architecture/protocol.md`, «Туман на сервере»; провал нагрузки — решение владельца.
- [ ] **T9. Docker и деплой**: multi-stage distroless non-root образ, `docker-compose.yml` с Caddy (TLS, wss), GitHub Actions: сборка образа, деплой на staging по `main`.

## Порядок

T1 → T2 → T3 → T8 → T4 → T5 → T6 → T7 → T9. Нагрузочный тест (T8) идёт сразу после сервера и тумана, до клиентской сети.

## Вне объёма

Аккаунты, рейтинг, магазин, порталы, реклама.
