Решения: воркер ≈ 30–35 МБ базовых + 3–4 МБ на комнату; кучу воркера ограничивает `SHARD_HEAP_MB` (192); `MemoryMax` службы 1200 МБ для сервера на 2 ГБ; для 512 МБ — `SHARDS=1`, `MemoryMax=300M`.

## Хаос-тест сети (`tools/replay/src/net-chaos.test.ts`, виртуальное время, ≈ 18 с)

30 клиентов в одной комнате, у каждого свой пинг 10–120 мс (+ разброс), случайные обрывы, «чёрные дыры» 3–12 с, скачки задержки до 300 мс, шторм (все рвут связь разом), восемь клиентов без связи 60 секунд (сервер замечает через 20 с, через 30 с управление у бота, при возврате снова у игрока), читер с флудом и подбором токенов.

| Показатель | Результат |
| --- | --- |
| Тиков матча / переподключений | 2400 / 266 |
| Полных снимков из 266 переподключений | 10 (остальные ≈ 256 возобновились дельтами) |
| Команд выдано / потеряно / исполнено дважды | 3296 / **0** / **0** |
| Передано боту и возвращено | 8 из 8 |
| Макс. отставание клиента после успокоения | 4 тика |
| Тик сервера p99 / макс (30 людей в комнате) | 8,7 / 11 мс |

Тест нашёл ошибку протокола: после долгого обрыва клиент досылал накопившиеся команды пачкой, сервер резал их лимитом 20 в секунду, а клиент считал отказ окончательным (63 потерянные команды). Исправлено: сервер принимает только следующий по порядку номер, лимит и пропуск — повтор (`retry`/`rateLimit`), клиент досылает порциями по 8 каждые 120 мс.

## Что делает сервер при перегрузе (тик комнаты дольше 100 мс)

1. У каждой комнаты свой срок и ритм 10 Гц, фазы разнесены; самые просроченные идут первыми, поэтому время делится честно.
2. Один тяжёлый тик задерживает соседей по шарду только на свою длину; после порции 20 мс хост отдаёт цикл событий (подтверждения, команды). Соседи на других шардах не замечают.
3. Долг до 300 мс догоняется подряд; больше — сбрасывается: игра в этой комнате идёт медленнее реального времени, лавины догоняющих тиков нет. Каждый сброс считается (`droppedTicks`) и пишется в журнал.
4. Шард с недавним сбросом или занятостью > 90% помечается `overloaded`: новые комнаты ему не даются, игроки получают «сервер занят»; идущие матчи доигрываются. Если перегружены все шарды, вход закрыт.
5. Геймплей не урезается: боты и симуляция считаются полностью, меняется только скорость хода времени. Проверено тестами на комнате с тиком 150 мс (`apps/server/test/overload.test.ts`).
