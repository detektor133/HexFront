## 04/T13 — фронт едет за границей без скачков

### Что сделано

- **Одна функция смены владельца гекса** — `setHexOwner` (`packages/sim/src/state/hex-owner.ts`). Меняет владельца и сразу переносит фронты, у которых есть грань этого гекса (с любой стороны); остальные фронты не трогает. Защитный тест в `test/guards/sim-guards.test.ts` не даёт записать `owner[…] =` в `packages/sim/src` мимо неё.
- **Перенос по контуру** — `followEdges` (`state/front-follow.ts`, примитивы контура — `state/contour.ts`):
  - грани, оставшиеся на границе, не меняются;
  - пропавший конец держится за свой внешний угол: угол на границе — конец на месте; ушёл — конец переезжает на ближайшую грань границы не дальше 2 граней (если такая есть) в той же связной части; из равных — участок длиннее, затем меньший EdgeId;
  - середина идёт по контуру в прежнем направлении обхода, не кратчайшим путём; участок не схлопывается;
  - граница разорвалась краем карты — фронт сохраняет все уцелевшие грани кусками; окружённый свой гекс выпадает; выбывание соседа фронт не сдвигает (подтверждено владельцем, `gdd/07-controls.md`).
- **Снимок = план**: `planViews` отдаёт `plan.edges` как есть; `frontEdgesNow` и периодический `followBorder` в системах фронта и наступления удалены.
- **Клиент**: линия фронта перетекает в новое положение за `motion.map` = 250 мс с кривой `motion.easing` (`apps/client/src/dev/front-tween.ts`); при `prefers-reduced-motion` — сразу.
- **Бенчмарк**: у каждого из 30 игроков синтетического матча — армия с фронтом по куску границы с соседом (`packages/sim/bench/synthetic.ts`), чтобы замер включал перенос фронтов.

### Риски

- Фронт, нарисованный инструментом, может идти «зигзагом» (соседние в списке грани не всегда сходятся в углу) — так строит `frontEdgePath` из точек-граней. Случайные тесты этого не нашли; сценарий-тест добавлен в приёмку T14.

## 04/T14 — линия наступления гладкая, без петель

План одобрен владельцем с поправками (`DECISIONS.md` 2026-09-27): кривая сглаживает середины граней, а не проходит через них; при равенстве — меньший EdgeId; петли в команде вырезаются молча; скриншоты до/после рядом; нормализация фронта — отдельная задача T14a.

### Что сделано

- **Sim** (`state/edge-line.ts`): `canonicalEdge` — одна грань — один `EdgeId` (меньший из двух сторон); `normalizeLine` — грань, пришедшая в уже пройденный угол, обрезает линию до этого угла (возврат стирает, петля вырезается); `offensiveEdgePath` — точки к одному `EdgeId` → путь по суше → нормализация. `setOffensiveLine` проверяет и применяет линию через `offensiveEdgePath`: грань с двух сторон — одна грань, петля вырезана без отказа.
- **Клиент, росчерк** (`dev/stroke-path.ts`, `dev/plan-draft.ts`): между углами — путь из кратчайших с наименьшей суммой расстояний углов до отрезка, который прошёл палец (при равенстве — меньший EdgeId по порядку граней); черновик держит последнюю точку пальца; линия после каждого шага — `normalizeLine`, поэтому возврат в пройденный угол стирает линию до него. Подсветка черновика — `offensiveEdgePath`, как в sim.
- **Клиент, вид** (`dev/plan-arrows.ts`, `dev/plan-layer.ts`): кривая — опорные точки = середины граней, два прохода скользящего среднего [1, 2, 1] / 4, затем 3 прохода Чайкина; концы — в концах линии. Стрелки — `arrowPairs`: начала равномерно по длине кусков фронта, концы — по длине кусков линии; куски линии развёрнуты и упорядочены по направлению фронта; разрывы между кусками в длину не входят.
- **Замкнутый контур (риск T13)**: сценарий-тест (`front-loop.test.ts`) — остров 3 × 3 и 5 × 5 внутри чужой земли, фронт 55–90 % контура, все сдвиги начала участка, захват каждого гекса внутри участка. Не упал: фронт остаётся с той же стороны, уцелевшие грани на месте. `coverArc` не менялся; тест остаётся регрессионным.
