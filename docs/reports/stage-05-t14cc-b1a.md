# 05/T14cc-Б1a — эталонный пересчёт снабжения на копии

## Изменение

Тест `packages/sim/test/supply-network-index.test.ts` теперь использует один основной стейт. Ручной тик повторяет `step`: очищает события, применяет команды, выполняет первые пять `SYSTEMS`, делает изолированную копию для пересчёта текущей фазы, затем выполняет оставшиеся системы с `createEconomyContext(state).incomeBases` и увеличивает `tick`.

`cloneState` остался только для проверки хэша: первые 100 ручных тиков сравниваются с отдельным вызовом `step`; внутри 1000-тикового цикла `cloneState` не вызывается. Проверка gen-карты сохраняет 1000 тиков, 30 игроков и `warCommands`.

## Поля копии

- `hexes.network`: `recomputeNetworks` записывает идентификаторы сетей в этот массив (`packages/sim/src/state/network.ts:69-78`); копируется через `slice()`.
- `networks`: `recomputeNetworks` заменяет массив сетей (`packages/sim/src/state/network.ts:84-85`); копируется через `slice()`, поскольку существующие объекты сетей не мутируются.
- `supplyRatios`: `recomputeSupply` удаляет старые и записывает новые коэффициенты (`packages/sim/src/state/supply.ts:204-208`); создаётся новый `Map`.
- `units`: `recomputeSupply` меняет `supplyLevel` и `encircled` (`packages/sim/src/state/supply.ts:211-215`); создаётся новый массив, а объекты отрядов текущей фазы клонируются.

Копия не разделяет с основным стейтом изменяемые массивы, `Map` и объекты отрядов. Кэш `lossCaches` привязан к объекту стейта через `WeakMap`, поэтому копия получает отдельный кэш.

## Проверка

Команда:

```text
pnpm vitest run packages/sim/test/supply-network-index.test.ts
```

Результат: 3 теста прошли, включая хэш-сравнение ручного тика с `step` на 100 тиках. Профиль gen-карты отдельно: 10,72 с; полный файл: 11,75 с. Решением владельца порог изменён на `≤12 с локально`; критерий выполнен. CI коммита `4e66559` зелёный.
