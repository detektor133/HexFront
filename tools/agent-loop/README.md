# Agent loop

`pnpm agent:run` — один исполнитель разработки на ПК владельца. Коммитит только он (сессии `codex exec` по скиллам), поэтому ветка не расходится. Запущенный цикл не завершается. Когда работы нет, раз в `--poll-seconds` (30) он делает условный запрос к GitHub с ETag по Issues с меткой `agent` и `main`: ответ 304 «ничего не изменилось» не тратит лимит API, git и codex не запускаются. Изменение (новая или правленая Issue, снятая `agent-stop`, мерж PR этапа) сразу запускает полный шаг; Enter в консоли — тоже. Полный шаг без изменений (git fetch, очередь) — раз в `--poll-minutes` (10) и после паузы на сбой codex.

Флаги: `--max-rounds 3` — кругов ВОЗВРАТ на задачу; `--max-minutes 120` — предел одной сессии codex (по таймауту дерево процессов останавливается, на Windows через `taskkill`); `--poll-seconds 30`; `--poll-minutes 10`; `--resume NN/Tn` — доделать незакоммиченную работу этой задачи; `--once` — выйти, когда работы нет; `--dry-run` — только план. `GITHUB_TOKEN` (права Issues RW, Actions R, Contents R; для PR этапа — Pull requests RW) нужен для Issues и CI.

## Шаг цикла

1. Ветка равна «Ветка» в `docs/STATUS.md`. Грязное дерево: недоделка своей задачи (`.ai-logs/agent-loop/state.json` или `--resume`) — сессия `$task NN/Tn продолжить`; иначе исполняется только Issue `$done`, остальное ждёт.
2. `git fetch`, fast-forward, push своих незапушенных коммитов; при расхождении — rebase, конфликт откатывается и цикл ждёт.
3. Issues: открытые, автор — владелец репозитория, метка `agent`, без `agent-stop`, самая старая первой. Первая строка тела — команда (`$decide`, `$bug`, `$split NN/Tn`, `$task NN/Tn`, `$accept NN/Tn`, `$review NN/Tn`, `$done NN/Tn`, `$stage-close`), дальше текст владельца; тело уходит в codex дословно. Успех — новый коммит, чистое дерево, зелёный CI → комментарий «выполнено» и закрытие. Иначе комментарий «стоп» с концом ответа и метка `agent-stop`; снять её — повторить. `$task` и `$review` идут кругами до `[x]`.
4. Этап закрыт (`Текущий этап` ≠ номер ветки): PR в `main` (или ссылка, если токену нельзя PR), ожидание Merge; после мержа — `$stage-close` создаёт ветку следующего этапа.
5. «Очередь»: `[~]` — `$review`; `[ ]` — `$next` → CI → `$review` (`AGENT_ROLE=reviewer`, правки только по `permissions.json`). `ВОЗВРАТ` — снова `$next`. Красный CI — один повтор `$next` (он начинает с починки CI). Ответ `$next` с `$split NN/Tn` — сессия `$split`, второй раз для той же задачи — ожидание владельца. Ответ с `$accept NN/Tn` — сессия `$accept`, затем `$next` снова, один раз за круги. Незакоммиченная работа — одна сессия `$task NN/Tn продолжить`.
6. Очередь пуста и в файле этапа нет `[ ]`/`[~]` — `$stage-close`.

## Ожидание владельца

Задача владельца, вопрос, проверка владельцем, исчерпанные круги, повторный `$split`, неудачная доделка: строка `жду: …` один раз и пауза до нового коммита — обычно Issue владельца (`$done NN/Tn <что сделано>`, `$decide …`, `$bug …`). Сбой codex (ненулевой код или «hit your usage limit» даже с кодом 0) — пауза 30 минут, затем повтор. Перезапуск цикла снимает ожидание и паузу: следующий шаг пробует снова.

Консоль: `→`/`←` сессий с итогом и путём к логу, `… идёт N мин` раз в минуту, `… жду CI`, `CI зелёный/красный`, `ВОЗВРАТ`, `готово`, `жду:`, `сбой:`. Те же строки — `.ai-logs/agent-loop-<дата>.md`; полный вывод сессий — `.ai-logs/agent-loop/<время>.log`; всё вне git.
