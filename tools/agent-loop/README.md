# Agent loop

`pnpm agent:run` — один исполнитель разработки на ПК владельца. Коммитит только он (сессии `codex exec` по скиллам), поэтому ветка не расходится. Запущенный цикл не завершается. Когда работы нет, раз в `--poll-seconds` (30) он делает условный запрос к GitHub с ETag по Issues с меткой `agent` и `main`: ответ 304 «ничего не изменилось» не тратит лимит API, git и codex не запускаются. Изменение (новая или правленая Issue, снятая `agent-stop`, мерж PR этапа) сразу запускает полный шаг; Enter в консоли — тоже. Полный шаг без изменений (git fetch, очередь) — раз в `--poll-minutes` (10) и после паузы на сбой codex.

Флаги: `--max-rounds 3` — кругов ВОЗВРАТ на задачу; `--max-minutes 120` — предел одной сессии codex (по таймауту дерево процессов останавливается, на Windows через `taskkill`); `--poll-seconds 30`; `--poll-minutes 10`; `--resume NN/Tn` — доделать незакоммиченную работу этой задачи; `--once` — выйти, когда работы нет; `--dry-run` — только план. `GITHUB_TOKEN` (права Issues RW, Actions R, Contents R; для PR этапа — Pull requests RW) нужен для Issues и CI.

## Шаг цикла

1. Ветка равна «Ветка» в `docs/STATUS.md`. Грязное дерево: недоделка своей задачи (`.ai-logs/agent-loop/state.json` или `--resume`) — сессия `$task NN/Tn продолжить`; иначе исполняется только Issue `$done`, остальное ждёт.
2. `git fetch`, fast-forward, push своих незапушенных коммитов; при расхождении — rebase, конфликт откатывается и цикл ждёт.
3. Issues: открытые, автор — владелец репозитория, метка `agent`, без `agent-stop`, самая старая первой. Первая строка тела — команда (`$decide`, `$bug`, `$split NN/Tn`, `$task NN/Tn`, `$accept NN/Tn`, `$review NN/Tn`, `$done NN/Tn`, `$stage-close`), дальше текст владельца; тело уходит в codex дословно. Успех — новый коммит, чистое дерево, зелёный CI → комментарий «выполнено» и закрытие. Иначе комментарий «стоп» с концом ответа и метка `agent-stop`; снять её — повторить. `$task` и `$review` идут кругами до `[x]`. Исполненная Issue в прежнем виде (тот же `updated_at`) 10 минут не берётся снова: список Issues GitHub отстаёт на секунды и ещё показывает её открытой.
4. Этап закрыт (`Текущий этап` ≠ номер ветки): PR в `main` (или ссылка, если токену нельзя PR), ожидание Merge; после мержа — `$stage-close` создаёт ветку следующего этапа.
5. «Очередь»: `[~]` — CI → `$review`; `[ ]` — `$spec` → `$next` → CI → `$review` (`AGENT_ROLE=reviewer`, правки только по `permissions.json`). Перед ревью цикл ждёт CI на HEAD (workflow `ci`, быстрые тесты), если сам ещё не видел его зелёным. Workflow `slow` (все тесты с тяжёлыми) цикл не ждёт: перед каждой задачей он один раз спрашивает его итог на HEAD. Идущий или непроверенный — работа дальше; красный — сессия `$task NN/Tn CI красный: slow <прогон>` задачи из трейлера `Этап:` коммита HEAD, второй красный после неё или коммит без задачи (служебный `NN/infra`) — ожидание владельца с подсказкой: упал сам прогон — «Re-run failed jobs» на GitHub, упал тест — ссылку Claude. Это ожидание цикл проверяет каждый шаг: прогон, перезапущенный на том же HEAD, зеленеет — работа идёт дальше без нового коммита и перезапуска. Красный `slow` прогона, который новый коммит обогнал, цикл увидит уже на прогоне нового HEAD. `ВОЗВРАТ` — снова `$next`. Красный CI (упал job) — сессия `$task NN/Tn CI красный: <прогон>`, не больше двух раз за круги. CI, который не удалось проверить (сеть, таймаут, 401), — не красный: пауза 30 минут и повтор проверки. Ответ `$next` с `$split NN/Tn` — сессия `$split`, второй раз для той же задачи — ожидание владельца. Ответ с `$accept NN/Tn` — сессия `$accept`, затем `$next` снова, один раз за круги. Незакоммиченная работа — одна сессия `$task NN/Tn продолжить`.
   Приёмочные тесты (если в `roles.json` есть роль `spec`): перед первой работой над задачей сессия `$spec NN/Tn` (`AGENT_ROLE=spec`, правки только по `permissions.json`, без коммита) пишет тесты критериев; цикл сам правит их `eslint --fix` и `prettier --write`, оставшиеся ошибки lint один раз возвращает `$spec`, второй раз — ожидание владельца; цикл запоминает их содержимое в `state.json` и передаёт исполнителю строкой запроса и `AGENT_LOCKED` (хук прав не даёт их менять). После работы цикл сверяет их с HEAD: не закоммичены или изменены — ожидание владельца. Остановка исполнителя с вопросом — цикл убирает тесты из дерева и вернёт их перед следующей работой. `ВОЗВРАТ` со строкой `СПЕК:` или со ссылкой на файл приёмочного теста (в ответе ревью или в блоке задачи) открывает тесты исполнителю: следующая работа идёт `$task NN/Tn` без `AGENT_LOCKED`, со строкой «исправь их сам по замечанию» (без ослабления проверок и заглушек ради теста), `$spec` их заново не пишет, ревью получает список исправленных тестов и сверяет их заново. Исполнитель, остановившийся на сломанном тесте (lint, окружение), пишет строку `СПЕК:` — `$spec` чинит тест по ней, работа исполнителя остаётся в дереве и продолжается сессией `продолжить`; то же замечание снова или больше трёх по задаче — ожидание владельца. `[x]` — тесты забываются.
6. Очередь пуста и в файле этапа нет `[ ]`/`[~]` — цикл ждёт `slow` на HEAD до конца (до 25 мин); зелёный — `$stage-close`, красный — исправление, как в п. 5.

## Консоль

В терминале цикл занимает весь экран (как `htop`) и перерисовывает его сам:

```
╭─ HexFront · агентный цикл ───────────────────────────── этап 07 · stage-07 · 09:42:05 ─╮
│ ◆ Нужен ты: w2 — 3 ВОЗВРАТ подряд по 07/T4 — нужно решение владельца                   │
│   [П] дать ещё круги  [Л] лог сессии                                                   │
├─ АГЕНТЫ · работают 2 · можно до 3 одновременно ────────────────────────────────────────┤
│ АГЕНТ    ЗАДАЧА     СОСТОЯНИЕ    ЧТО ДЕЛАЕТ                                      ВРЕМЯ │
│ главный  07/T1      ● работает   пишет код ($task 07/T1)                         2 мин │
│ w1       07/T3      ● работает   ждёт CI на GitHub (CI 07/T3)                    3 мин │
│ w2       07/T4      ◆ ждёт тебя  3 ВОЗВРАТ подряд по 07/T4 — нужно решени…       2 мин │
│ w3       —          ○ свободен   без задачи                                            │
├─ ЭТАП 07 · ветка stage-07 ─────────────────────────────────────────────────────────────┤
│ [████████▒▒░░░░░░░░░░░░░░░░░░░░] 5 из 18 готово · 1 на ревью · осталось 12             │
│ Дальше: 07/T6 → 07/T7 → 07/T8 → 07/T9 → 07/T10                                         │
├─ ЗА ЭТОТ ЗАПУСК · 13 мин ──────────────────────────────────────────────────────────────┤
│ задач готово 3 · возвратов с ревью 1 · сессий codex 9 (58 мин) · CI ✓ 5 ✗ 1            │
├─ ЖУРНАЛ · полный: .ai-logs/agent-loop-2026-10-14.md ───────────────────────────────────┤
│ 09:39:05 [w1 07/T3] … жду CI 07/T3                                                     │
│ 09:40:05 [w2 07/T4] жду: 3 ВОЗВРАТ подряд по 07/T4 — нужно решение владельца           │
│                                                                                        │
│                                                                                        │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ Лог последней сессии codex: главный .ai-logs/agent-loop/<сессия>.log                   │
│ [+] больше агентов  [-] меньше  [1-4] сколько  [Enter] проверить сейчас  [Q] выход     │
╰────────────────────────────────────────────────────────────────────────────────────────╯
```

Верх отвечает на главный вопрос: нужен ли ты (жёлтым, причина целиком — до 4 строк — и клавиши ответа под ней), пауза после сбоя (снимется сама) или всё идёт само. В таблице — каждый агент: задача, состояние, что делает словами и сколько; при пределе больше 1 видны и свободные места потоков. Журнал — последние строки протокола (ошибки красные, ожидание владельца жёлтое, готовое зелёное, строки потоков — цветом потока); весь протокол — в файле из заголовка журнала, полный разговор последней сессии codex — в логе внизу.

Клавиши — без Enter, в любой раскладке: `+` / `-` — на одного агента больше или меньше, `1`–`4` — столько агентов, Enter — проверить Issues и `main` сейчас, `Q` дважды — выход (Ctrl+C — сразу); вставленный текст командой не считается. Ответ на ожидание — буквой из строки под причиной (русская буква или латинская на той же клавише): `П` — повторить шаг, как перезапуск цикла, но без выхода (у исчерпанных кругов — «дать ещё круги»: задача получает новые `--max-rounds` кругов); `З` — перезапустить упавшие jobs прогона `slow` на GitHub (нужен `GITHUB_TOKEN` с правом «Actions: Read and write»; без него — открой ссылку и «Re-run failed jobs»), ожидание снимается, цикл работает дальше, пока прогон идёт (перезапуск кнопкой на сайте снимает его так же); `О` — открыть ссылку из причины в браузере; `И` (и `Д`, если в причине две команды — например, «$decide» на вопрос и «$done 07/T2» на свою проверку) — открыть готовую Issue с командой из причины: останется дописать текст и нажать «Create»; `Л` — открыть лог последней сессии codex этого агента. Клавиши отвечают ожиданию в баннере (первому сверху); ожидание, которое снялось само (дерево чистое, `slow` не красный), из баннера уходит; ответ текстом (вопрос, `$decide`) — по-прежнему Issue. Число агентов с клавиатуры — то же, что Issue `$streams N`: запоминается и применяется, как только цикл закончит текущий шаг (в режиме одного агента — после текущей сессии). Выход останавливает идущие сессии codex; начатая задача доделается при следующем запуске, хвост журнала остаётся в терминале. Окно меньше 60×16 — просьба его увеличить; `NO_COLOR=1` — без цвета; вывод не в терминал (в файл) — прежние строки с временем.

## Потоки (`$streams N`)

Предел — Issue `$streams 2` (с меткой `agent`, как другие команды) или флаг `--streams 2`; цикл запоминает его в `.ai-logs/agent-loop/state.json` и меняет режим на ходу, без перезапуска: `$streams 1` — снова один агент в главном каталоге (задачи, уже начатые в потоках, доделываются там), `$streams 2`…`4` — до N задач одновременно (ADR 0011). N — только верхняя граница: сколько задач идёт на деле, цикл решает сам по `Файлы:` и `После:`. Каталоги потоков — `<репозиторий>-streams/w1`, `w2` рядом с репозиторием (worktree, создаются сами, `pnpm install` в каждом); ветка задачи — `agent/NN-Tn`, CI идёт и на ней. Цикл берёт первую задачу «Очереди», у которой закрыты задачи из `*После:*` и `*Файлы:*` не пересекаются с задачами в работе; без этих строк задача идёт одна. В потоке: `$spec` → `$task NN/Tn` → CI → `$review`; потом очередь слияния по одной задаче: свежая ветка этапа вливается в ветку задачи (конфликт — сессия `$task NN/Tn слияние` и повторный `$review`; те же рабочие файлы или файлы вне `Файлы:` — повторный `$review`), CI на слитом дереве, fast-forward ветки этапа. Главный каталог: Issues, `slow`, `$stage-close` (только когда потоки свободны); работа владельца в нём (грязное дерево) задерживает только слияние. Issue, изменившая задачу в работе, отменяет её поток — задача начинается заново. Перезапуск цикла продолжает задачи по веткам каталогов потоков. Строки потоков в протоколе — с префиксом `[wN NN/Tn]`; полный вывод их сессий — в `.ai-logs/agent-loop/` каталога потока.

## Ожидание владельца

Задача владельца, вопрос, проверка владельцем, исчерпанные круги, повторный `$split`, неудачная доделка: строка `жду: …` один раз и пауза до нового коммита — обычно Issue владельца (`$done NN/Tn <что сделано>`, `$decide …`, `$bug …`). Сбой codex (ненулевой код или «hit your usage limit» даже с кодом 0) — пауза 30 минут, затем повтор. Перезапуск цикла снимает ожидание и паузу: следующий шаг пробует снова; в консоли то же для одного ожидания — клавиша `П`.

Консоль: `→`/`←` сессий с итогом и путём к логу, `… идёт N мин` раз в минуту, `… жду CI`, `CI зелёный/красный/не проверен`, `ВОЗВРАТ`, `готово`, `жду:`, `сбой:`. Те же строки — `.ai-logs/agent-loop-<дата>.md`; полный вывод сессий — `.ai-logs/agent-loop/<время>.log`; всё вне git.
