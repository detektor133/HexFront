# Agent loop

`pnpm agent:run` последовательно выполняет задачи в ветке этапа. Веток задач, worktree и параллельных исполнителей нет.

## Автомат задачи

1. Цикл сверяет ветку с `docs/STATUS.md`, подтягивает origin и выбирает первую открытую задачу строки «Очередь».
2. `plan` проверяет измеримость задачи. Его изменения остаются локальными.
3. `$task` реализует один механизм вместе с тестами и создаёт локальный атомарный коммит. Отдельный `$spec` доступен только по ручной команде владельца.
4. Цикл запускает все тесты задачи из общего diff и `pnpm verify --changed` после рабочего коммита. Hook запрещает push; цикл дополнительно сверяет remote ref.
5. `$review` только читает локальный diff и отвечает `OK` либо всеми блокерами вида `КОД:`/`ТЕСТ:`.
6. Цикл хранит блокеры в `.ai-logs/agent-loop/state.json` и передаёт замечания к коду и тестам одному исполнителю. После исправления reviewer проверяет весь пакет.
7. Когда очередь блокеров пуста, полный review заново проверяет весь diff задачи.
8. Только после `OK` оркестратор push-ит ветку и ждёт последний push-run обязательных workflow точного `HEAD`.
9. После зелёного CI оркестратор ставит задаче `[x]`, обновляет `STATUS.md`, создаёт служебный docs-коммит, push-ит его и ждёт его CI.

Красный CI становится одним пунктом `КОД:` и проходит тот же цикл исправления. Сеть, 401 или таймаут не считаются красным CI: цикл делает автоматическую паузу и повторяет проверку.

## Состояние и перезапуск

`activeTask` содержит номер задачи, исходный SHA, фазу (`work`, `review`, `target-review`, `ci`, `finalize`, `docs-ci`) и очередь блокеров. После перезапуска цикл продолжает эту фазу и не выбирает новую задачу. Stage-файл не используется как шина сообщений reviewer.

Незакоммиченное дерево не передаётся новой задаче. Для явной доделки используется `--resume NN/Tn`; чужие изменения цикл не откатывает.

## Issues владельца

Цикл читает открытые Issues владельца с меткой `agent`. Команды `$decide`, `$bug`, `$done`, `$split`, `$accept` и `$stage-close` выполняются только в заявленном объёме. Владелец нужен для задачи владельца, отсутствующего решения, внешнего доступа или опасного действия.

## CI

`pnpm ci:wait --all-workflows` запрашивает GitHub Actions с `head_sha=<HEAD>&event=push`, выбирает последнюю попытку по `run_number`, `run_attempt`, `id` и не принимает старый завершённый run. Workflow `slow.yml` проверяется отдельно.

Workflow с изменениями только документации завершается зелёным на текущем SHA. Результат предыдущего коммита не наследуется.

## Запуск

Основные флаги: `--max-minutes 120`, `--poll-seconds 30`, `--poll-minutes 10`, `--resume NN/Tn`, `--once`, `--dry-run`. Параметр `--streams` оставлен только для совместимости и принудительно сводится к `1`.

`GITHUB_TOKEN` нужен для Issues и GitHub Actions. Полные логи лежат в `.ai-logs/agent-loop/`; локальное состояние — `.ai-logs/agent-loop/state.json`.
