# $review

Режим приходит в первой строке запроса. Он определяет весь объём ревью.

## Reviewer кода

Строка `Режим reviewer кода` означает: проверяй только код продукта, реальный путь вызова,
критерии, запреты и регрессии в изменённом коде. Тесты не читай, не оценивай и не возвращай.
При `OK` отметь задачу `[x]`: это передаёт код отдельному автору тестов, а не завершает задачу.
При дефекте продукта верни обычный `ВОЗВРАТ` с `файл:строка`, критерием и наблюдаемым поведением.

## Reviewer тестов

Строка `Режим reviewer тестов` означает: код уже принят. Проверь только тесты реальных путей,
критерии и крайние случаи. Не меняй код или тесты.

- Слабый либо отсутствующий тест: `ТЕСТ: <файл:строка> — <минимальная регрессия, при которой тест останется зелёным>`.
- Невыполненный критерий в продукте: `КОД: <критерий> — <наблюдаемое поведение> — <файл:строка>`.

`ТЕСТ:` получает только автор тестов. `КОД:` получает только исполнитель. Не смешивай их
в одном пункте. Визуальное подтверждение владельца записывай в отчёт, не делай возвратом.

## Общие правила

Прочитай блок задачи и родительский блок. На повторном ревью проверь прошлый возврат и только
строки, изменённые после него; не добавляй новый блокер к неизменённому коду или тесту. Первый
возврат обязан перечислить все найденные блокеры сразу. Полный `pnpm verify` не запускай.

Первой строкой напиши `OK` либо `ВОЗВРАТ`. Сохрани результат в файле этапа: `OK` — `[x]`,
возврат — `[ ]` и последний непустой блок `Возврат ревью:`. Создай docs-коммит с трейлером
`Этап: NN/Tn` и push. Код и тесты не изменяй.
