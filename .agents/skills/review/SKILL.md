# $review

Скилл запускается владельцем вручную в новой сессии или ролью reviewer. Прочитай блок задачи целиком и блок её родителя с запретами, без сокращений, и diff всех коммитов с её трейлером. Если запрос перечисляет приёмочные тесты (их написал `$spec` до кода), сначала сверь каждый с текстом задачи: числа, формулы, путь вызова, каждый ли критерий закрыт. Тест не совпадает с задачей или не проверяет критерий (даже если зелёный) — `ВОЗВРАТ`, строка замечания начинается с `СПЕК:`, называет файл теста и что он не проверяет; по ней тест исправит исполнитель. Если запрос говорит, что исполнитель исправлял приёмочные тесты по возврату `СПЕК:`, сверь их с текстом задачи заново: ослабленная проверка, подгонка кода под тест, скрытые элементы или заглушки ради теста — `ВОЗВРАТ`. Для каждой строки `Заменён тест: <файл>:<строка> — «<цитата>»` в коммитах задачи и для каждого изменённого существующего теста без такой строки проверь: цитата дословно есть в блоке задачи и прямо задаёт новое поведение, новая проверка проверяет его не слабее старой, остальные проверки теста не ослаблены и не удалены; иначе — `ВОЗВРАТ` с замечанием по файлу теста. Полный `pnpm verify` не запускай: его выполняет CI на этом коммите. Для каждого критерия и сторожа найди тест, измерение или команду чтением. По коду проверь, что каждый критерий выполнен на реальном пути вызова, а не только во вспомогательной функции, которую вызывает тест; хардкод или обходной путь вместо механизма из задачи — `ВОЗВРАТ`. На каждый запрет выполни `rg` по изменённым файлам и приведи вывод. При критерии скорости запусти только замер `pnpm --filter @hexfront/bench full-match --players=30,100 --minutes=1` и сравни с базой задачи.

Первой строкой ответа напиши `OK`, если всё подтверждено, иначе `ВОЗВРАТ` и список `пункт — файл:строка — что не так`. Код и тесты не изменяй. При `OK` замени `- [~]` на `- [x]`; если это последняя подзадача после `$split` и все подзадачи родителя теперь `[x]`, отметь `[x]` и родителя. Добавь строку в отчёт и создай docs-коммит с трейлером `Этап: NN/Tn`. При `ВОЗВРАТ` замени `- [~]` на `- [ ]`, под задачей добавь строку «Возврат ревью:» со списком и создай такой же docs-коммит. В обоих случаях — push ветки.

Строка запроса «Поток wN: ветка agent/NN-Tn …» — задачу ведёт параллельный поток: работай в его ветке и пушь её; `docs/STATUS.md` не меняй. Строка «Повторное ревью после слияния ветки этапа: <причина>» — задача уже `[x]` в ветке потока, а в неё влились изменения ветки этапа; проверь diff задачи вместе со слиянием по названной причине (те же файлы, разрешённый конфликт, файлы вне «Файлы:» задачи). При `OK` отметку не меняй и коммит не делай; при `ВОЗВРАТ` — `[ ]` и docs-коммит, как обычно.
