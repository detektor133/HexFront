# $done <этап/задача> [слова владельца]

Владелец сам сделал задачу владельца (обучение, плейтест) или проверку, которой ждёт задача (скриншоты, приёмка владельцем). Слова владельца после номера задачи — его отчёт, переносятся дословно.

1. Сравни текущую ветку с полем «Ветка» в `docs/STATUS.md`. Если они не совпадают, остановись и сообщи владельцу.
2. Прочитай блок задачи целиком и блок её родителя с запретами, без сокращений. Если задача не задача владельца и `docs/STATUS.md` не говорит, что она ждёт проверки владельцем, — не выполняй и скажи ровно: «NN/Tn не ждёт владельца — запусти `$task NN/Tn`».
3. `git status --short`. Каждый изменённый или новый файл должен быть результатом команды, которую задача поручает владельцу (например, для обучения — `packages/sim/src/bots/weights*.json` и `docs/reports/evolve/`). Если есть другой файл — перечисли его и остановись, ничего не коммить.
4. Если результаты есть — один коммит с ними по `docs/CONVENTIONS.md`: тип из текста задачи (веса и числа баланса — `balance:` с трейлером `Решение:`), трейлер `Этап: NN/Tn`. Сами результаты не правь.
5. Отметь задачу `- [x]` — работу владельца `$review` не проверяет. Если слова владельца говорят, что проверка не пройдена, задачу не отмечай и скажи: «Запиши замечания через `$bug` или `$decide`».
6. `docs/STATUS.md`: что сделал владелец (его слова дословно), какие коммиты, следующая задача очереди. Коммит `docs` с трейлером `Этап: NN/Tn`, push.
7. Код и тесты не трогай, verify и матчи не запускай.
8. Ответ владельцу — 2–3 строки: коммиты и следующая задача.
