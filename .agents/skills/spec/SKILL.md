# $spec <этап/задача>

Ты пишешь только тесты. Код, доки, файл этапа и `docs/STATUS.md` не трогаешь; коммит и push не делаешь. Тесты остаются в рабочем дереве: до кода они красные, исполнитель закоммитит их вместе с кодом и менять не сможет.

1. Прочитай блок задачи целиком и блок её родителя с запретами, без сокращений (не через `-C2`). Источник ожиданий — только текст задачи, её родителя, GDD и `docs/gdd/10-balance.md`. Как задача уже сделана в коде, не смотри: тест проверяет замысел, а не реализацию.
2. На каждый критерий «Приёмки» и каждое правило задачи с числом, формулой или порогом — отдельный `it`. Название по-русски цитирует критерий с его номером. Числа — дословно из текста.
3. Тест идёт через реальный путь вызова: публичная функция пакета, `step` с командами, CLI или отчёт инструмента — то, через что результат увидят игрок или владелец, а не вспомогательная функция. Кода, которого ещё нет, импортируй по пути и имени из текста задачи; если текст их не называет — выбери один путь в пакете, который меняет задача, и назови его в ответе: исполнитель создаст код там.
4. Формулу проверяй на маленьких синтетических данных с ответом, посчитанным вручную в комментарии теста, а не повтором формулы. Для каждой формулы — хотя бы один случай, где неверная формула дала бы другой ответ (например, «по своим метрикам» против «по худшему игроку»).
5. Запрет задачи, который виден в коде (нет констант, нет вызова, нет прохода по всей карте), — тест-сторож чтением исходника, как в `packages/sim/test/guards/`.
6. Тест идёт не дольше 4 с. Матчи ботов, скриншоты и решения владельца тестом не проверяются: перечисли такие критерии в ответе, их закрывают `$accept` и владелец.
7. Файлы — новые `*.test.ts` в `test/` или `src/` пакета, который меняет задача. Существующий тест меняй, только если задача прямо называет его заменяемым.
8. Критерий, по тексту которого нельзя однозначно сказать ожидаемый результат, тестом не закрывай: назови его в ответе — вопрос запишет исполнитель.
9. Отформатируй свои файлы `pnpm exec prettier --write <файлы>`. Тесты не запускай ради зелёного: до кода они падают, это ожидаемо.

Если запрос содержит «Замечания ревью к приёмочным тестам», исправь тесты по этим замечаниям, остальные не меняй.

Ответ — до 10 строк: какие критерии каким тестом закрыты, какие не тестом и почему. Последняя строка ровно `СПЕК: <путь>, <путь>` или `СПЕК: нет`, если ни один критерий не проверяется тестом.
