# $task <этап/задача>

Пример: `$task 05/T3`. Если номер не указан — остановись и спроси номер.

## Порядок

0. В начале выполни `pnpm ci:wait` для `HEAD`. Красный CI из-за кода (тесты, типы, lint) сначала исправь. Красный CI по причине вне кода (403, раннер, сеть) не исправляй инфраструктуру: запиши блокер в `docs/STATUS.md` и продолжай, если локальный `pnpm verify` зелёный. Затем проверь `git status --short`; если дерево не чистое, остановись и сообщи владельцу.
1. Найди задачу через `rg -l`, затем прочитай только её блок критериев через `rg -n -C2` по 1–2 файлам. Если задача затрагивает больше одной подсистемы (армии, дороги, экономика, бот, бой, UI, инструменты) или содержит больше 4 критериев — не начинай и скажи: «запусти `$split NN/Tn`». Если задача является задачей владельца (плейтест, приёмка или пометка «задача владельца»), не выполняй её и скажи: «Очередь дошла до NN/Tn — это задача владельца».
2. Контекст: раздел «Следующая сессия» в `docs/STATUS.md`, последние 10 строк `docs/DECISIONS.md`. Остальные документы — только нужные разделы через `grep -n -C5`, по таблице «механика → раздел GDD» в AGENTS.md.
3. Если в документах нет ответа на дизайн-вопрос — запиши вопросы одним списком в `docs/QUESTIONS.md`, выведи их владельцу и остановись. Код до ответа не писать.
4. Тесты на критерии приёмки и краевые случаи. Матчи ботов внутри задачи запрещены; для задач интерфейса также запрещены ботоматчи. Итерацией считается только падение теста по проверке (`assertion`) или golden-теста. Ошибки типов, сборки, импортов, lint и prettier в коде, который пишет сама задача, итерацией не считаются — их просто исправляй. После двух неудачных итераций остановись и подготовь отчёт. Проверки тестов ради зелёного результата не меняй никогда. Не добавляй диагностики и метрики сверх критериев. Предлагай `$accept NN/Tn` только если в критериях задачи явно указан ботоматч.
5. Минимальный код. Проверка — только `pnpm verify --changed`, детали ошибок — `grep -n -C3` по логу из `.ai-logs/`, не перезапуск.
6. Один полный `pnpm verify` без `--changed` выполни перед коммитом. Golden-тесты всегда входят в проверку.
7. Коммит по `docs/CONVENTIONS.md` с трейлером `Этап: <NN>/<Tn>`. Текст коммита — через временный файл.
8. Отметь задачу `- [x]` в файле этапа.
9. `docs/STATUS.md`: раздел «Следующая сессия» — что сделано, следующая задача, какие файлы читать, до 30 строк.
10. Push ветки этапа. CI после push не жди.
11. Отчёт владельцу до 10 строк: что сделано, решения, которые стоит знать, следующая задача, последняя строка полного `pnpm verify`. Про CI напиши ровно: «CI не проверен, проверится в начале следующей сессии». Не используй слова «принято» и «приёмка завершена».

## Запрещено

- Картинки, видео, браузер, ручной `pnpm dev` и Playwright.
- Фоновые задачи с опросом: длинные команды — на переднем плане с таймаутом.
- Задачи вне текущей; найденный баг — строкой в `docs/BUGS.md` с классом по `docs/PROCESS.md`, раздел «Баги и замечания». В текущей задаче чинится только Б1, который мешает её критериям; Б2 и Б3 не чинить.
